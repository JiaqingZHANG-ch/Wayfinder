# 深度长谈 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新用户第一天照旧 3 分钟出计划；之后 4 个晚上对完账，各聊一次（现状 / 方向 / 能量 / 三个五年版本 + 智囊团），每次的结果当晚改第二天的计划。

**Architecture:** 后端新加纯逻辑模块 `src/mentor/deep_talk.py`（屏幕定义、邀请规则、导师一句回应、各步提议、「投资自己」候选），`council.py` 加一组「看三个版本」的函数，`db.py` 加 `deep_talks` 表，`api.py` 加 `/deep-talk*` 接口并把「保存设置」「合并对账」抽成两个共用函数。App 加全屏路由 `app/deep-talk.tsx`，入口放在对账完成页、「我」页、建档最后一屏；时间线给原型习惯加「为了：…」。

**Tech Stack:** FastAPI + SQLite + pytest（`uv run pytest -q`，从仓库根目录）；Expo SDK 58 / expo-router / reanimated 4 / TypeScript（`npx tsc --noEmit`、`npx expo lint`，从 `mobile/`）。

**Spec:** `docs/superpowers/specs/2026-11-21-deep-talk-design.md`（第 10 节是审稿后定下的实现决定，和正文冲突时以第 10 节为准）。

## Global Constraints

- 所有回复、文案、代码注释用中文；代码标识符用英文。
- 不主动问焦虑和家庭；「关系」一项可以跳过；不存回避的话题、言行矛盾这类字段。
- 用户原话一字不改；三个版本、方向、目标的原文来自用户，导师只能提议措辞，用户改了或点「对」才算。
- 所有用户自由文字在提交那一刻先过 `screen()`（危机检查）；所有模型输出先过 `model_output_is_crisis`；危机时返回 `crisis_reply()`，不存这一段。
- 导师的一句回应、方向、能量公式都过 `tone.banned_hits`，命中两次用兜底句。
- 导师和智囊团只提议；写进档案、习惯、计划、`tomorrow_task` 都要用户点「好 / 对」。
- 习惯最多 `MAX_HABITS = 3`，不改这个数。
- 档案来源用已有的 `"深度长谈"`（`PROFILE_SOURCES`），层级用已有的 `PROFILE_LEVELS`。
- 旧接口不改，只加；旧的 `run_council` 不改（旧 NiceGUI 界面在用）。
- 前端沿用「天色」设计规范（`docs/design.md`）和对账页的全屏版式、组件（`Button`、`Card`、`Small`、`Title`、`Glyph`、`EnergyPick`、`Pressy`）。
- 每次长谈目标 10 分钟、最多 15 分钟；当天报的电量 ≤ 2 的晚上不邀请。
- 不推送、不合并到 main；只在分支 `deep-talk` 上提交。试用数据库 `var/app.db` 用完删掉。

- Produces:
  - `STEPS: dict[int, dict]` —— 每一步 `{"name": str, "screens": list[dict]}`；屏 `{"id", "kind", "question"?, "hint"?, "items"?, "options"?}`。`kind` 取值：`scores / open / follow / energy / version / council / rate / choose`。具体内容（照抄）：
    - 1「现状」：`{"id": "scores", "kind": "scores", "items": ["健康", "学习或工作", "玩", "关系"], "options": ["关系"]}`（`options` = 可跳过的项）；`{"id": "lift", "kind": "open", "question": "这几项里，你最想让哪一项往上走一点？为什么是它？"}`；`{"id": "more_time", "kind": "open", "question": "最近最想多花点时间在哪一件事上？"}`
    - 2「方向」：`{"id": "why", "kind": "open", "question": "你现在学的、做的，最终是为了换来什么？说一件具体的事。"}`；`{"id": "worth", "kind": "open", "question": "五年后回头看，这几年怎样过算没白过？"}`
    - 3「能量」：`{"id": "flow", "kind": "open", "question": "最近一次做事做到忘了时间，是在做什么？"}`；`{"id": "follow", "kind": "follow", "options": ["在哪", "和谁", "用什么"]}`；`{"id": "energy", "kind": "energy"}`
    - 4「三个版本」：`{"id": "v1", "kind": "version", "question": "照现在的路走下去", "hint": "五年后的你在做什么、住在哪、每天怎么过？"}`；`{"id": "v2", "kind": "version", "question": "现在这条路走不通了", "hint": "你会换哪条路？那条路上的一天是什么样？"}`；`{"id": "v3", "kind": "version", "question": "不考虑钱和别人怎么看", "hint": "你会过什么样的日子？"}`；`{"id": "council", "kind": "council"}`；`{"id": "rate", "kind": "rate", "items": ["资源", "喜欢", "信心", "和自己一致"]}`；`{"id": "choose", "kind": "choose"}`
  - `next_screen(answers: dict[int, dict], step: int) -> str | None` —— 这一步第一个没答的屏 id；`council` 屏在 `answers[4]` 里有 `"council_seen": true` 才算答过。
  - `should_invite(rows: list[dict], *, checked_in: bool, energy_level: int | None, today: date) -> bool` —— 全部为真才邀请：今晚已对账；`energy_level is None or energy_level > 2`；4 步没全做完；当前步那一行的 `snoozes < 3`；今天没有开始或完成过任何一步（看 `started_at` / `finished_at` 的日期）。
  - `reply(model: ModelPort, question: str, answer: str) -> tuple[Literal["ok", "crisis"], str]` —— 一句回应；不提新问题、不给建议；两次命中禁用说法或模型出错就回兜底句 `FALLBACK = "这句话我记下了。"`。
  - `propose(model: ModelPort, step: int, answers: dict) -> tuple[Literal["ok", "crisis"], dict]`：
    - step 1 → `{"observation": str | None}`（≤ 60 字；失败为 None）
    - step 2 → `{"direction": str, "mismatch": bool}`（direction ≤ 40 字，只用他说过的内容；失败时 direction = `worth` 的原话截到 40 字，mismatch False）
    - step 3 → `{"formula": str | None}`（≤ 40 字；失败为 None）
    - step 4 → `{"mission": str, "goals": list[str], "prototype": {"title": str, "minutes": int, "floor_min": int} | None, "tomorrow": str | None}`（goals ≤ 3 条、每条 ≤ 30 字；title ≤ 20 字；minutes 5–180、floor_min 1–minutes；失败时 mission = 选中版本原话截到 40 字，其余为空）
  - `INVEST: list[dict]`（照抄）：`{"key": "read", "title": "看书", "minutes": 30, "floor_min": 10, "when": "睡前"}`、`{"key": "move", "title": "运动", "minutes": 30, "floor_min": 10, "when": "下午或傍晚"}`、`{"key": "review", "title": "写一段复盘", "minutes": 10, "floor_min": 5, "when": "对账前"}`、`{"key": "sleep", "title": "睡前放下手机", "minutes": 20, "floor_min": 10, "when": "睡前"}`、`{"key": "skill", "title": "练技能", "minutes": 30, "floor_min": 10, "when": "精力最好的时段"}`
  - `invest_suggestions(answers: dict[int, dict], habits: list[dict]) -> list[dict]` —— 最多 2 条，每条是 `INVEST` 的一项加 `"why": str`。规则：`len(habits) >= MAX_HABITS` 返回 `[]`；默认顺序 read, move, review, sleep, skill；第 1 步 `lift` 原话里有「健康 / 身体 / 运动 / 睡」→ move、sleep 提到最前；第 3 步 `energy` 里标了 `love` 的事、标题含「学 / 课 / 练 / 语 / 写 / 读 / 编程」→ skill 提到最前；已有习惯标题里含同类词的跳过（read：看书 / 读；move：运动 / 健身 / 跑 / 走；review：复盘 / 日记；sleep：睡 / 手机；skill：练）。`why` 由程序写：因健康提前的写「你说想让『{lift 原话前 12 字}』往上走一点」；因热爱提前的写「你说做『{那件事的标题}』的时候最有劲」；其余写「{title}每天{floor_min}分钟起步，花得少、回报长」。

- Produces（接口，状态结构 `DeepTalkState`，所有 `/deep-talk*` 都返回它，危机时返回 `crisis_reply()`）：

```

 "steps": [{"step": int, "name": str, "status": "todo" | "doing" | "done"}],

```

  - `POST /deep-talk/answer {"step": int, "screen": str, "value": Any}` —— 按屏的 `kind` 校验 `value`：`scores` 是 `{项: 0–10}`（可跳过的项可以缺）；`open / version` 是 1–`MAX_INPUT` 字的字符串（先 `screen()`）；`follow` 是 `{选项: 字符串}` 最多 2 项（每项先 `screen()`）；`energy` 是 `{energy_items 的 id: 三档或 null}`，立刻用 `save_settings` 写进设置并重排今天；`rate` 是 `{"0"|"1"|"2": {四项: 1–5}}`；`choose` 是 `0 / 1 / 2 / null`。`open` 屏回 `reply`；一步的最后一屏答完：调 `propose`，把档案类结果用 `db.propose_profile(..., source="深度长谈")` 存成待确认（step 1 → `近期观察`；step 2 → `方向`；step 3 → `近期观察`（能量公式）；step 4 → `使命`、每条目标一条 `目标`、原型标题一条 `策略`），把原型习惯和 `invest_suggestions` 的结果存进 `answers["4"]["proposals"]`，`tomorrow` 存进 `answers["4"]["tomorrow"]`，然后写 `finished_at`。第一次答这一步时写 `started_at` 并把这一步的 `snoozes` 清零。屏 id 不是 `next_screen` 给的那个时返回 409。
  - `POST /deep-talk/snooze` → 当前步那一行 `snoozes + 1`。
  - `POST /deep-talk/council` —— 三个版本都答了才能开（否则 409）；`council_status` 置 `running`，在 `threading.Thread(daemon=True)` 里跑 `run_versions_council`，结束写 `council` 和 `done / failed`；危机写 `failed` 并 `db.log_crisis`。重复调用时状态已是 `running / done` 就不重开。`GET` 时 `answers["4"]["council_seen"]` 由 App 用 `POST /deep-talk/answer {"step": 4, "screen": "council", "value": true}` 写入。
  - `POST /deep-talk/confirm {"kind": "profile" | "habit" | "tomorrow", "id": int | null, "key": str | null, "content": str | null, "accept": bool}` —— profile：`accept` 为真调 `db.confirm_profile(id, content)`，为假不确认（留在待确认里不再显示：在 `answers` 里记下 `dismissed` 的 id）；habit：`accept` 为真时习惯满了返回 409「习惯满了，先在设置里换掉一个」，否则把它加进设置（`source`；原型习惯的 `goal_id` = 这一轮第一条已确认的「目标」档案 id，没有就 None），走 `save_settings`，排不下返回 422 且提议保持 pending；tomorrow：`accept` 为真时 `merge_log(day, {"tomorrow_task": content 或提议原文}, {"tomorrow_task"})`。
  - `POST /deep-talk/restart` → 新的一轮（`round + 1`），旧的保留。
  - `GET /today` 加 `"goals": {habit_id: 目标原文}`：`habit_meta` 里 `goal_id` 指向一条已确认、且是最新一轮的「目标」档案时才有。
