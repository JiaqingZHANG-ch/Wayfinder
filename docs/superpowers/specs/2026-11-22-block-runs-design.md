# 做事陪跑：每一块的番茄钟、被打断、做完

## 为什么做

Wayfinder 定位收窄成**时间和精力管理**（精力块、时间块、番茄钟、排程），导师部分继续藏着（`mobile/src/features.ts` MENTOR=false）。

用户定的成功标准：「他每天知道该做什么，并且真的把排好的事做完。」

前一半已经有了：说一句话，求解器按精力排一天。后一半没有：白天从排好到做完，App 什么也不管，只在晚上对账问一句。用户说没做完的主要原因是**做到一半被别的事打断**，所以这一版管的就是做事那一段，重点是被打断以后怎么接上。

## 目标

1. 块开始时手机提醒。点进去看到正在做的块和番茄倒计时；不点也照计划时间开始计时。
2. 番茄钟真的走起来：块里每 30 分钟一个番茄（25 分钟专注 + 5 分钟小歇，`POMODORO_MIN = 30`），到点提醒休息、提醒回来。
3. 「被打断了」：计时暂停。「继续」时按停了多久处理（用户选的 C，分界 15 分钟）：
   - 不到 15 分钟（含 15）：后面的块往后推，不打扰；
   - 超过 15 分钟：弹出现有的提示条「要不要把其余的按精力重新排一下？」，点「重排」后用现有的前后对比列出改了几处。
4. 「做完了」：这一块记成做完，记下实际分钟数。提前做完，空出来的时间留给用户，不自动往前塞。
5. 晚上对账：白天点过「做完了」的事自动填成做了，只问没点过的。
6. 记下每块计划几点、实际几点开始、被打断几次各多久、几点做完。第一版只记不学。

## 不做的

- 从这些记录里学真实精力曲线、学要不要问重排（照 Linger「从反应里学」的做法，攒够几周数据再说）；
- 自动发现用户在干别的、锁屏专注模式、白名单 App；
- 统计图表、完成率页面；
- 「晚开始了」单独处理：v1 没有「开始」按钮，计时一律从计划开始时间算；
- 关掉块提醒的开关（v1 先不做，嫌吵只能在系统设置里关通知，见「我的决定」）。

## 反目标（技术上能跑，但这样就算失败）

- 每停一下计划就大变：小打断必须不动计划的其余部分，只往后顺延；
- 催人、让人有负罪感：文案不写「你又被打断了」「落后了」，只说事实和下一步；
- 往后推把后面的块**钉住**：钉住是用户在说「这块就放这儿」，顺延不是。钉死了以后点「重排」什么也动不了（这是做法 B 被否掉的原因）。

## 约束

- 沿用现有结构：FastAPI + SQLite（`src/server/`），求解器在 `planner/`，Expo SDK 58 App 在 `mobile/`。
- 所有重排都走 `api.py` 的 `reflow()`；新计划用 `db.add_plan` 存成新版本。
- 课（class）、吃饭和路上（life）、用户说的固定事项、钉住的块（pinned）都不能被往后推挤动。life 块例外，见下面的推法。
- 用户写的字照旧过 `screen()`。这一版的新接口没有用户文字，所以不调模型。
- 新表要进 `USER_TABLES`、`migrate_pg`、supabase 迁移（加 RLS）、`docs/data-inventory.md`，并在隐私说明里补一句。`PRIVACY_VERSION` 升到 v5，老用户要重新同意。
- 仓库是公开的通用模板，个人数据只放 gitignored 目录或 scratchpad。
- 不推送、不合并，等用户每次亲口说。

## 做法（讨论过的三种）

| | 做法 | 结论 |
|---|---|---|
| **A** | 服务器记每一块的进度：新表加开始、打断、继续、做完几个接口；「继续」时后端算停了多久，决定往后推还是请 App 问重排 | **选这个**。接得上现有的重排、晚上对账和以后的学习；计时以服务器时间为准，App 关掉再开不丢 |
| B | 只在手机上记，往后推时一块块调 `/plan/edit` | 否掉：`/plan/edit` 会把块钉住，推一次后面全钉死，重排动不了；数据也只在手机上，晚上对账和以后学习拿不到 |
| C | 把打断当一件固定事项塞进今天，然后重排 | 否掉：每次打断都会重排，和用户选的「15 分钟以内只往后推」对不上 |

用户说的是「代码我来写」，所以选 A 是我的决定；用户回了「好」。

## 设计

### 数据：`block_runs` 表

一行对应今天的一块，`(user_id, day, block_id)` 唯一：

| 字段 | 意思 |
|---|---|
| `started_at` | ISO 时间（带时区，取 `clock()`）。第一次点按钮时写入，值是**计划开始时间**（当天日期 + 块的 `start`），不是点按钮的时刻 |
| `pauses` | JSON 数组 `[[from, to], …]`，最后一段没继续时 `to` 是 null |
| `done_at` | 点「做完了」的时间，没点是 null |
| `planned_start` / `planned_end` | 第一次点按钮时块的计划起止（HH:MM），给以后学精力曲线用 |

只有点过按钮才有这一行。一整天什么都没点的块没有记录，晚上照旧问。

块的 id 在往后推、做完时都不变，重排时已经开始的块也原样保留（`reflow()` 里 `replan_after` 把开始早于现在的块当过去留着），所以按 block_id 记是稳的。块被删掉或被 `/day/say` 换掉以后，留下的记录就没人用了，不清理。

### 哪些块有按钮

可以操作的块：`must`、`proj`、`flex`，以及带 `item_id` 的块（当天事项；和 `/plan/edit` 的「能改」规则一致）。课和吃饭没有按钮。

App 上「现在」卡显示哪一块：

1. 有暂停着、还没做完的块，显示它（你是从它那里被打断的）；
2. 否则显示开始时间不晚于现在、结束时间晚于现在、还没做完的那一块；
3. 都没有就不显示卡。

### 接口（都不带 version，按今天最新的计划办）

做事中途因为版本过期弹 409 太打扰，所以三个接口都直接读最新版。块不在最新版里就 404，块不能操作就 422，状态不对就 409（比如还没暂停就点继续，或者已经做完了）。

**`POST /block/{id}/pause`**
- 没有记录就新建，`started_at` 写计划开始时间；
- 追加一段 `[now, null]`；
- 不改计划，不出新版本。

**`POST /block/{id}/resume`**
- 关掉最后一段暂停，停了 `g = now − from` 分钟；
- 把这一块的结束时间往后推 g 分钟（这一块本来就在做，不钉住）；
- 然后看情况：
  - `g ≤ 15`：按下面的推法把后面的块往后推。推得开就存成新版本，返回 `ask_reflow: false`；推不开（会撞上动不了的块，或者超过上床时间）就不推后面的，只存延长后的这一块，返回 `ask_reflow: true` 和 `overlaps`；
  - `g > 15`：同样只存延长后的这一块，返回 `ask_reflow: true` 和 `overlaps`。App 弹出现有的提示条，点「重排」调现有的 `/plan/reflow`，这一块开始早于现在，会原样保留；
- **延长有上限**：这一块延长后不能伸进后面动不了的块（class、钉住的、说的固定事项），也不能超过上床时间，最多延长到那一块的开始。延长不够的那几分钟，在重排的时候体现出来（`ask_reflow: true`）。
- 返回 `today_body(day)`，加上 `ask_reflow` 和 `overlaps`。
  - 这里的 `overlaps` 是**新的算法**：被延长的这块和后面没推开的块之间，凡是撞上的、不是自由时间的块都算（两边都列出来）。
  - 现有的 `overlaps()` 只算和钉住的块撞的，不能直接拿来用。
- App 拿到 `overlaps` 以后，照手动拖动那样描琥珀色边。时间轴现在只在重排路径上收到 `before`，这里要把 `overlaps` 也传进去，具体怎么传由 builder 决定。

**`POST /block/{id}/done`**
- 只能对已经开始的块点：块的计划开始时间晚于现在时返回 409。「现在」卡也只会显示已经开始的块。
- 实际分钟数 = `done_at − started_at − 暂停总时长`，在 `/today` 的 `runs` 里算好返回。
- 写 `done_at = now`；正在暂停的话先关掉那一段；
- 如果现在早于计划结束时间，把这一块的结束时间改成现在（取整到 5 分钟，至少 `MIN_BLOCK` 分钟；短于这个就不改时间），存成新版本，后面的块不动；
- 返回 `today_body(day)`。

**往后推的推法**（只用在 `g ≤ 15`）：

- 从被延长的那块往后，按开始时间依次看每一块：`新开始 = max(原开始, 前一块的新结束)`，时长不变；不重叠就停（中间的空档把推移吸收掉了）。
- 能挪的：`must`、`proj`、`flex`、`life`（吃饭晚 10 分钟没关系），而且没钉住、不是当天说的固定事项。
- 挪到撞上不能挪的块（class、钉住的、说的固定事项），或者结束晚于上床时间，就算推不开。
- `free-` 开头的自由时间块不挡路：被压到的部分直接剪掉，剪到不足 `FREE_MIN_GAP`（30 分钟）就删掉。
- 推出来的块保留原 id，`pinned` 不变。

**新版本的确认状态**：原来那一版已经确认过的话，继续和做完生成的新版本也直接标成确认，免得「用这个计划」按钮又冒出来。
- `db.add_plan` 现在不能直接存成已确认，要给它加一个参数。
- `in_calendar` 不跟着带过来，日历也不重写，见「我的决定」。

**时间和时区**：`started_at` 和各段暂停都用 `clock()` 给的、带时区的时间。计划开始时间换成时刻的办法是：逻辑日 `day` 的日期，加上块的 `start`，用 `clock()` 的同一个时区。块都在起床到上床之间，不会跨过午夜。

### 提醒

由后端算进 `/today` 的 `reminders`。只算今天的，`later_reminders` 不加块提醒。

- 新加两种 kind：`block`、`pomodoro`，`url` 都是 `/`。
- `todays_reminders` 现在拿不到时钟，也拿不到 runs。两种做法都行：给它加参数，或者在 `today_body` 里另外拼上去，由 builder 选。
- 开始时间已经过了的块不再提醒。App 现在每次拿到 `/today` 都会全部清掉再重新定（`notifications.native.ts`），所以只要后端算对，手机上就对。

- **块开始**：今天每个可操作、还没开始、没做完的块，在开始时间提醒。标题「到点了：{title}」，正文「{start}–{end}」，点开回首页。
- **番茄**：只算正在走、没暂停的那一块。专注时间从 `started_at` 算起，扣掉暂停时长；每个番茄第 25 分钟提醒「休息 5 分钟」，第 30 分钟提醒「回来接着做」。块的最后一个番茄不提醒回来。只定还没到点的。
- 网页版没有本地通知（`notifications.ts` 是空实现），只看卡上的倒计时。

### App

**「现在」卡**：放在今天页时间轴上面，选哪一块见上面的规则。

```
┌───────────────────────────────┐
│  现在  15:15–16:45            │
│  前线训练 W1D1 Git            │
│  ███████░░░░░  第 2 个番茄 18:40 │
│                               │
│  [ 被打断了 ]    [ 做完了 ]     │
└───────────────────────────────┘
```

- 暂停中：按钮换成「继续」，倒计时停住，旁边显示「停了 6 分钟」；
- 倒计时完全按 `/today` 返回的 `runs` 和手机时钟算，每秒更新。专注时显示「专注 还剩 mm:ss」，小歇时显示「小歇 还剩 mm:ss」；
- 「继续」返回 `ask_reflow: true` 时，显示现有的重排提示条，并给撞上的块描琥珀色边，和手动拖动之后一样。点「不用」收起，用户自己拖。

**`/today`** 多返回 `runs: {block_id: {started_at, pauses, done_at}}`，只含今天的。

**时间轴**：做完的块打一个勾，颜色变淡。正在做的块不另外标，看「现在」卡就行。

**晚上对账**：对账能记的事来自 `_items(plan)`：习惯和可选项按块 id，项目按 task_id。

- 一件事今天所有的块都点过「做完了」，就预先填成 `done`，在问答流程里跳过「做没做」这一问；
  - 项目照样问「比预想多还是少」（`vs_plan`），一点就过；
  - App 提交对账时，要把预先填好的这几项一起带上；
- 汇总页照样列出来，可以改；
- 只做完了一部分的，照常问。

## 我的决定（用户可以改）

1. 没有「开始」按钮，计时从计划开始时间算。「晚开始」不单独处理。
2. 「继续」之后，这一块本身总是往后延长 g 分钟，延长时不钉住它。
3. 三个接口不带 version，直接按最新版办。
4. `g` 等于 15 也算小打断（≤ 15）。
5. 提前做完：只把这一块截短，后面的不往前挪。
6. 新版本沿用原来的确认状态，日历不跟着改。`shortcut:` 日历里会和手机上差几分钟，开了日历同步再补。
7. 块提醒没有关闭开关。
8. 隐私说明升到 v5，老用户要重新同意。
9. 被删的块留下的记录不清理。
10. 「继续」之后延长的部分，不能伸进课、钉住的块和说的固定事项，也不能超过上床时间。
11. 项目做完以后，「比预想多还是少」仍然问用户，不按实际分钟数自动判断。
12. 还没开始的块不能点「做完了」。

## 测试（builder 写细节）

- **暂停**：建记录时 `started_at` 是计划开始时间；连点两次暂停返回 409；课和吃饭的块返回 422；计划不出新版本。
- **继续，停 ≤ 15**：
  - 后面的块整体往后推，中间有空档的地方吸收掉；
  - `pinned` 不变，id 不变；
  - 撞上课时不推，这一块最多延长到课开始，返回 `ask_reflow` 和 `overlaps`；
  - 推过上床时间也一样不推；
  - 自由时间块被剪短或删掉；
  - 停正好 15 分钟算小打断。
- **继续，停 > 15**：只延长这一块，返回 `ask_reflow`；接着调 `/plan/reflow` 时，这一块原样保留，其余重排。
- **做完**：
  - 提前做完会截短，并取整到 5 分钟；
  - 太短的不截；
  - 暂停中直接点做完，会先关掉那段暂停；
  - 做完以后再点暂停返回 409。
- **确认状态**：原版已确认的，新版本也是确认的。
- **提醒**：
  - 块开始提醒只给可操作、没开始、没做完的块；
  - 番茄提醒扣掉暂停时长；
  - 暂停中不给番茄提醒。
- **`/today`**：带 `runs`。
- **对账**：全做完的事预先填成 done；一件事拆成两块、只做完一块的，照常问。
- **隐私**：`/export` 包含 `block_runs`，`DELETE /me` 会删掉它；隐私说明是 v5。
- **App**：`tsc` 和 `expo lint` 通过。
- **浏览器端到端**（假时钟）：
  1. 「现在」卡出现；
  2. 点被打断 → 继续（停 5 分钟），后面的块往后推；
  3. 再停 20 分钟，出现提示条，点重排，列出改了几处；
  4. 点做完了，块打勾；
  5. 晚上对账时这件事已经填好。
- **真机**：通知响不响、准不准、番茄提醒，要用户在 iPhone 上试。
